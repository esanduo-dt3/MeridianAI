# Product overview

## What Meridian is

Meridian combines block-based notes, documents and tasks with an agent that answers questions from the workspace's own content. Its claim is narrow and meant to be measurable: **trustworthy because inspectable.**

- Every answer links to the exact chunk it used, with character offsets, not just a file name.
- Every answer shows a confidence value that is explicitly labelled **uncalibrated**.
- Answers that are low-confidence or fail the groundedness check go to a person for review instead of being presented as fact.
- The agent can propose a task, but nothing is written until a person approves it.

## Reliability note

This text, or a faithful short form of it, must appear in the UI, the README and the demo narration:

> AI-generated answers and agent actions may be incomplete or wrong. Every answer carries a chunk-level source citation and a stated, uncalibrated confidence value. Low-confidence or ungrounded answers are routed to human review.

## Non-negotiables

These come from the build brief and are not relaxed under any circumstance.

1. **No auto-execute.** No agent-proposed write reaches the database without explicit human approval.
2. **Content is data.** Document and tool-returned content is passed to the model as data, never concatenated into instructions or system context. Only a user's own turn can trigger a tool call.
3. **Cited and labelled.** Every answer cites a specific chunk with character offsets, and carries a confidence value labelled uncalibrated. A bare number is never shown.
4. **MUST scope only.** SHOULD and COULD items wait for an explicit go-ahead after a gate passes.

## Week 1 scope

**MUST:**
- Google sign-in, workspace-scoped auth
- Block-based note editor stored as a block tree
- PDF and Word upload, chunked into a real `chunks` table
- Hybrid retrieval: dense plus sparse search, rerank, grading, retry, groundedness self-check
- Ask the agent, with clickable chunk-level citations and a labelled-uncalibrated confidence
- Agent proposes a task from a note or conversation, held for approval, written with reasoning once approved
- Full audit log; admin review queue for flagged answers and actions
- Prompt-injection defence by structural isolation, proven against the red-team suite
- Pipeline health dashboard backed by real `retrieval_runs` data

**SHOULD (only after a gate passes and the owner says go):** backlog and sprint board, automatic task assignment by role, undo on agent actions.

**COULD (not this week):** whiteboard canvas, flow or diagram view, Google Calendar sync.

**Owner-approved additions:** user-created workspaces with Admin and Member roles, and email invites. See [D-006](../decisions.md#d-006) and [D-007](../decisions.md#d-007).

## Build gates

| Gate | When | Pass | If it fails |
| --- | --- | --- | --- |
| G1 | End of Day 3 | At least 12 of 15 golden questions answered with the correct source chunk cited | Cut the retry loop, ship rerank-only, say so explicitly |
| G2 | End of Day 4 | Propose, hold, approve and write works end to end for at least one real task | Switch to auto-execute with full reasoning logged, cut the approval UI, carry it as a SHOULD, say so explicitly |

The golden set of 15 questions and the 8 red-team documents are authored by people, independently of the model under test. They are never generated by the build.

## Targets

- **Latency:** p50 under 8 seconds per question, end to end. The retry loop is the first thing cut if this is missed.
- **Red-team suite:** 8 of 8 injection attempts caught, reported honestly whatever the result.
